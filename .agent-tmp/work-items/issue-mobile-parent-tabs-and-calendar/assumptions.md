# Assumptions: issue-mobile-parent-tabs-and-calendar

## 需求與問題根因分析
1. **為什麼會出現 10/19 的資料？**
   - 根因一：在 `Parent/Index.cshtml.cs` 中，`allCurrentSlots` 載入了目前進度下的所有時段，未過濾掉今天（`TodayDate`）之前的歷史過期時段。
   - 根因二：當目前 7 天（如 11/8 ~ 11/14）內沒有課堂時，`SelectedDate` 的 fallback 寫了 `SlotDates.Any() ? SlotDates.First() : null`，導致抓到了資料庫裡最早的舊種子時段（2026/10/19），並展開了「2026/10/19（週一）課堂列表（已截止）」。
   - 根因三：`DbInitializer.cs` 中的預設種子課堂日期若是過去日期，線上或展示環境在進入 11 月後就會沒有當週示範課堂。
   - 解決方案：
     1. `Parent/Index.cshtml.cs`：嚴格過濾只載入 `>= TodayDate`（今天及以後）的時段，今天之前的時段絕不再載入或顯示。
     2. `SelectedDate` 預設選取：只會在當前顯示的 `SevenDays`（7 天）內挑選有課堂的一天；若當前 7 天內無課堂，則 `SelectedDate = null`（不展開舊日期課堂，改顯示友善的當週課堂提示），絕不會跳出過去 10/19 的課堂！
     3. `DbInitializer.cs`：檢視種子資料，若示範時段全數在過去，自動補足當週示範時段，確保展示體驗完整。

2. **附件第一張：中間的 Tab 調整讓家長視覺上更方便看**
   - 現況問題：在手機寬度下，`線上預約時段`、`我的預約與候補 0` 在第一排，`堂數異動流水帳 6` 掉到第二排置中，形成上下不對稱、灰底大塊的凌亂視覺；頂部學生資訊卡也分成 5 行鬆散排列。
   - 優化設計：
     - 將中間 3 個 Tab 設計為**現代化三等分滿版導覽列（3-Column Segmented Tab Bar）**，在手機與桌機上皆維持整齊劃一的單列 3 格並排，字體清晰、計數徽章精緻醒目，家長一眼看清三大功能並輕鬆單手切換。
     - 微調頂部學生卡片在手機上的緊湊度（頭像與學生選單同行、在學狀態與堂數/LINE 狀態整齊排列）。

3. **附件第二張：日曆重新設計（主要在手機模式下使用）**
   - 現況問題：
     - 原本將「星期列」與「日期格」分為兩個 7 欄 Grid，在手機螢幕（~375px）下，第一格因 `11/8` + `今天` 橫向並排被撐寬，導致後面 6 格被壓扁成窄條，且上下兩列完全沒對齊（`11/9` 對到 `週二`）。
     - 每格寬度僅 35~40px，放不下「小組指導」、「團體輔導」標籤。
   - 全新行動優先（Mobile-First）7 日曆設計：
     - **整合「星期 + 日期 + 狀態/標籤」於單一卡片**：不再分上下兩個獨立 Grid，徹底根除上下錯位問題。
     - **手機版專屬高易讀性佈局**：
       - 在手機螢幕下，採用 **高質感卡片網格（或直覺式週曆條）**：
         我們看怎樣在手機上最好看又最好點：
         如果手機上採用 **「上 4 下 3」雙排大卡片網格（或直列/雙欄式，或 7 日橫向精準等寬卡片）**？
         讓我們仔細思考兩種方案在手機上的視覺效果！
