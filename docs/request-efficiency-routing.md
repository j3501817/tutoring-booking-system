- The source file states that the downstream project observed repeated project discovery, missing validation environment placeholders, missing governance artifacts, and incomplete/corrupted issue text.

## Problem Summary

The previous template spent model work on deterministic setup and routing tasks:

- Detecting language and framework repeatedly per issue.
- Starting Codex on incomplete or corrupted issues.
- Running validation before local placeholder environment variables exist.
- Letting missing governance artifacts create a second repair cycle.
- Launching parallel Codex jobs before cheap routing checks complete.

## Template Adjustment Recommendations

### Shared Artifact Contract

Work-item artifact rules are centralized in:

```text
docs/schemas/work-item-artifacts.schema.json
```

The validator and wrapper both consume this contract. `work-item.json.requiredArtifacts` must match the shared contract, and GitHub Issue work items must include one completion artifact: `DELIVERY_REPORT.md` or `PM_Review.md`.

Template initialization runs a dry-run self-check:

```powershell
npm run agentic:contract:self-check
```

This creates a dry-run work item skeleton and validates it before operators start real issue automation.

### Project Profile Cache

The template now supports a generated project profile cache at:

```text
.agent-tmp/project-profile.json
```

Refresh command:

```powershell
npm run agentic:profile:refresh
```

The profile records language hints, application type, governance runtime, package manager, safe validation commands, focused validation commands, required environment placeholders, opt-in test markers, and refresh triggers. The cache is generated by `scripts/generate-project-profile.js` and referenced by the batch wrapper before Codex runs.

### Issue Completeness Preflight

`scripts/codex-batch-issues.ps1` now checks issue readiness before creating an implementation branch unless `-OverrideRoutingGates` is used. The gate checks:

- Empty or too-short body.
- Mojibake or replacement characters.
- Missing clear requested change.
- Missing acceptance criteria, expected behavior, or affected component.
- High-risk keywords or `risk:high` label.

Issues that fail are routed to `codex:manual-review` with `PM_Review.md`; no implementation branch is created by the default path.

### Context Pack

Every ready work item gets:

```text
.agent-tmp/work-items/<work-item-id>/CONTEXT.md
```

The context pack contains project profile summary, issue metadata, safe validation commands, focused validation commands, required placeholder environment variable names, opt-in tests, deterministic candidate file hints, and explicit scope boundaries.

Candidate files are hints only; Codex still must verify source truth from files it changes.

### Validation Env Bootstrap

`scripts/run-app-checks.js` reads `requiredEnvPlaceholders` from the project profile and injects local-only values for missing variables before running configured application checks.

Rules:

- Never write production secrets to artifacts.
- Placeholder names are logged; secret values are not required.
- Connectivity, e2e, external service, database, Blob, and Function Host tests remain opt-in by default.

### Governance Artifact Skeleton

Before Codex runs, the wrapper creates:

```text
work-item.json
issue.json
issue.md
CONTEXT.md
assumptions.md
PLAN.md
status.md
TEST_REPORT.md
DELIVERY_REPORT.md
```

Codex updates these files instead of creating governance structure from scratch. This prevents avoidable governance failures caused only by missing skeleton artifacts.

The skeleton is validated with `node scripts/validate-work-item.js --work-item <work-item-id>` before Codex is invoked.

### Keep Parallelism With Routing Gates

`MaxParallel` remains the concurrency control for Codex jobs. The wrapper now adds routing gates before execution:

- `intake`
- `manual-review`
- `ready-for-codex`
- `codex-running`
- `codex-failed`
- `pr-created`

High-contention route keys such as auth, data, delivery, infra, shared, and `area:*` labels are not run concurrently by default. Operators can use `-OverrideRoutingGates` for high-throughput batches.

### Per-Issue Execution Budget Guard

Each work item records:

- `queueState`
- `retryCount`
- `maxRetries`

The default policy is one Codex implementation run, one focused validation pass, and one final safe validation pass. Deterministic environment or governance recovery may be handled once; product behavior failures should route to PM review or a follow-up issue instead of cycling indefinitely.

### Pre-PR CI-Parity Gate

After Codex completes and before push or PR creation, the wrapper runs local CI-parity validation:

```powershell
node scripts/validate-work-item.js --work-item <work-item-id>
node scripts/check-secrets.js
node scripts/run-app-checks.js
```

If any command fails, no PR is created by default. The wrapper writes the result into `TEST_REPORT.md` and routes the work item to `PM_Review.md`.

After PR creation, the wrapper records PR check status in `DELIVERY_REPORT.md`.

## Suggested Prompt Changes

Avoid discovery-heavy prompt text such as:

```text
Detect the project language and framework before validation.
Prefer project-defined commands from README.md, CONTRIBUTING.md, Makefile, Taskfile.yml, justfile, package.json, or .github/workflows.
```

Use profile-based prompt text:

```text
Read AGENTS.md, .agent-tmp/project-profile.json, issue.md, and CONTEXT.md.
Use the existing project profile unless this issue explicitly requires changing project structure.
Use validation commands and required environment placeholders from the project profile and context pack.
Do not run opt-in tests unless the issue explicitly requires them.
Keep changes scoped to this issue.
Update TEST_REPORT.md and DELIVERY_REPORT.md.
```

## Operator Usage

See [request-efficiency-usage.md](request-efficiency-usage.md) for the operational workflow.

Common commands:

```powershell
npm run agentic:profile:refresh
.\scripts\codex-batch-issues.ps1 -DryRun -IssueJsonPath .\path\to\issues.json -MaxParallel 2
.\scripts\codex-batch-issues.ps1 -MaxParallel 2
```

Routing gates are enabled by default. Use `-OverrideRoutingGates` only when the operator has already reviewed issue contention and accepts the throughput tradeoff.

## Codex Work Items And Acceptance Criteria

1. Implement project profile generation and refresh.
   Acceptance: `npm run agentic:profile:refresh` creates `.agent-tmp/project-profile.json` with safe validation commands and refresh triggers.

2. Load project profile in the batch wrapper.
   Acceptance: a Codex prompt references `.agent-tmp/project-profile.json` when it exists and does not ask for broad rediscovery.

3. Add issue completeness and mojibake preflight.
   Acceptance: incomplete or corrupted issues produce `PM_Review.md`, receive manual-review handling, and do not create an implementation branch by default.

4. Generate `CONTEXT.md` for each work item.
   Acceptance: every ready work item includes project profile summary, issue metadata, validation commands, placeholders, opt-in tests, candidate file hints, and scope boundaries.

5. Add validation environment placeholder bootstrap.
   Acceptance: configured presence-check variables are populated with local-only placeholders before safe validation commands run.

6. Generate governance artifact skeletons before Codex execution.
   Acceptance: `npm run agentic:test` does not fail immediately after wrapper initialization due only to missing required artifacts.

7. Add queue states and retry budget tracking.
   Acceptance: `work-item.json` records `queueState`, `retryCount`, and `maxRetries`.

8. Preserve parallelism with routing gates.
   Acceptance: `MaxParallel` remains supported, but issues with the same deterministic high-contention route key wait unless `-OverrideRoutingGates` is used.

9. Update tests and dry-run coverage.
   Acceptance: dry-run covers a complete issue and an incomplete issue; complete issues get skeleton artifacts and context packs, incomplete issues route to manual review.

10. Update documentation.
    Acceptance: docs describe profile cache, preflight, context pack, env bootstrap, governance skeletons, routing gates, budget guard, prompt changes, and split work items.
